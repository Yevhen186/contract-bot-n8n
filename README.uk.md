# 📄 Contract Bot — генерація договорів за допомогою AI для логістичної компанії

[🇬🇧 English](README.md) | 🇺🇦 Українська

> Створено для реальної української експедиторської компанії й використовувалося в роботі (2025–2026).
> n8n · OpenAI · Google Drive/Docs/Sheets · Telegram

Менеджер-логіст скидає в Telegram **усе, що має по рейсу**: виписки з ЄДР (PDF), реквізити (Word), фото техпаспорта й посвідчення водія, голосове з цінами. У відповідь отримує **готові до підпису `.docx`**: договір із замовником і заявку перевізнику.

Вручну один договір займав 15–20 хвилин, а в IBAN і кодах ЄДРПОУ траплялися помилки. З ботом — близько 2 хвилин, і кожен код перевіряється за контрольною сумою ще до створення документа.

---

## ✨ Що вміє (v2)

- **Будь-які дані, у будь-якому порядку й кількості.** Текст, голос (Whisper), фото (GPT-4o Vision), PDF, Word. Кожне повідомлення зберігається в пачку; AI читає всю пачку разом, коли менеджер натискає **✅ Готово**.
- **Один рейс → обидва договори.** Режим «Обидва»: менеджер надсилає документи замовника, натискає **🚚 Далі: перевізник** і надсилає документи перевізника. Кожен документ позначається стороною, тож AI не плутає, хто є хто.
- **Перевірка перед генерацією.** Бот показує, що знайшов, чого бракує і де документи суперечать один одному. Менеджер виправляє голосом або текстом («адреса правильна 10025», «ціна перевізнику 15 000») — змінюється лише те поле, про яке сказано.
- **Детермінована перевірка після AI** (на цьому кроці AI не бере участі):
  - контрольні суми ЄДРПОУ / РНОКПП / IBAN;
  - якщо AI помилився в IBAN, правильний відновлюється з тексту документа (відстань Левенштейна ≤ 3 до валідних IBAN у документах);
  - реквізити нашої компанії ніколи не потрапляють у поля замовника чи перевізника;
  - правила ФОП і ТОВ (підстава «Виписки з ЄДР» або «Статуту», «директор» ФОП — це сам ФОП);
  - регістр ПІБ, короткі форми (ТОВ «…», ФОП …, Прізвище І.П.);
  - контроль маржі (попередження при збитку або марже < 8%), ПДВ за податковим статусом перевізника.
- **2 юрособи × 2 типи договорів**, шаблони в Google Docs із 40+ полями `{{PLACEHOLDER}}`.
- **Надійність:** повторні спроби на кожному зовнішньому виклику (завантаження з Telegram, OpenAI, Google) і окремий workflow помилок: менеджер отримує вибачення, адміністратор — вузол, текст помилки й посилання на виконання.

## 🏗️ Архітектура

```
Telegram ──► Template Config ──► Get Session (Sheets: Sessions_v2)
                                      │
                         Route by Step (Switch)
   ┌──────────┬──────────┬────────────┼──────────────┬───────────┐
  /start   скасувати  кнопка сторони  дані          ✅ Готово    правка
   │                     │            │                │            │
 компанія й роль     Set Side     маршрутизація     Get Inputs   Normalize Text
   │                 (замовник /  голос → Whisper   (Sheets)        │
 новий batch_id       перевізник) фото  → Vision       │            │
                                  pdf   → OpenAI       └──► Build AI Request ◄┘
                                  docx  → Drive→Docs         │  (extract | patch)
                                      │                  OpenAI (json_schema, strict)
                                Append to Inputs             │
                                (kind:сторона, text)     Post-process  ← контрольні суми,
                                                             │            виправлення IBAN,
                                                        Review Screen ──► Telegram   бізнес-правила
                                                             │
                                                  🚀 Генерувати (callback)
                                                             │
                                                      Generate Items (1–2 документи)
                                                             │
                                          Contract Generate (sub-workflow, на кожен документ):
                                          копія шаблону → batchUpdate replace →
                                          експорт .docx → надсилання в Telegram → видалення копії
```

| Workflow | Вузлів | Роль |
|---|---|---|
| `contract_bot_v2.json` | 74 | Діалог, збір даних, витягування AI, перевірка |
| `contract_generate.json` | 8 | Створює один `.docx` із шаблону й надсилає його |
| `contract_bot_error_handler.json` | 7 | Ловить збої, повідомляє менеджера й адміністратора |

Бізнес-логіка — у 5 звичайних JavaScript-файлах (`v2/01…05-*.js`). Вони вставляються в Code-вузли n8n **і** тестуються локально без n8n (`node v2/test-local.js`). Самі workflow генеруються з коду (`v2/build/build_v2.js`), тому JSON для n8n відтворюваний, а не відредагований вручну.

## 💡 Інженерні рішення

- **AI витягує, код вирішує.** Модель лише заповнює строгу JSON-схему. Усе, що має бути точним (контрольні суми, сторона компанії, наші реквізити, ПДВ, маржа), перевіряє детермінований код — і він покритий тестами.
- **Спершу пачка, потім один виклик AI.** Зібрати всі дані й обробити їх разом дешевше й точніше, ніж розбирати кожне повідомлення окремо: модель бачить виписку, реквізити й голосове одночасно і може розв'язати суперечності.
- **Сторона фіксується в момент отримання.** Кожен документ зберігає сторону, активну на момент надходження, тож файли, що завантажуються з різною швидкістю, не потрапляють не туди.
- **Режим виправлення (patch).** На кроці перевірки той самий збирач запиту передає поточні дані й нове повідомлення та просить модель змінити лише те, що попросили.
- **Workflow як результат збірки.** Node-скрипт генерує обидва workflow, додає повторні спроби на кожен зовнішній вузол і не збирає проєкт, якщо змішані облікові дані чи лишилися залишки v1.
- **Жодних персональних даних у репозиторії.** Тестові дані — вигадані компанії, коректні, але фіктивні IBAN і коди; секрети зберігаються лише в credentials n8n.

## 🚀 Як запустити

1. **n8n** (будь-який) і облікові дані: Telegram API, Google Sheets / Drive / Docs OAuth2, OpenAI (+ HTTP Header Auth `Authorization: Bearer …` для прямих викликів OpenAI).
2. **Google Sheets:** аркуш `Sessions_v2` з колонками `chat_id | step | company | role | data | updated_at | raw_input | batch_id`; аркуш `Inputs` з `chat_id | batch_id | kind | name | text | created_at`.
3. **Шаблони:** Google Docs із полями `{{PLACEHOLDER}}` (перелік — у `v2/01-template-config.js` → `FIELDS`), ID шаблонів — у `TEMPLATES`.
4. **Імпорт:** спершу `workflows/contract_generate.json`, потім `contract_bot_v2.json`, потім `contract_bot_error_handler.json`. Перепідключіть облікові дані, таблицю й sub-workflow у вузлі **Execute Workflow**; у Contract Bot v2 → Settings → Error Workflow оберіть обробник помилок.
5. Опублікуйте й надішліть боту `/start`.

Перезібрати workflow після змін у коді: `node v2/build/build_v2.js <ID workflow Contract Generate>`.
